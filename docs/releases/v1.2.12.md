## 用户反馈

> 希望支持安卓 7.0

## 结论：最低版本其实早已是 Android 7.0，但有三处会挡住 7.x 设备

`app/build.gradle.kts` 从 1.2.3 起就是 `minSdk = 24`（Android 7.0），并开启了 core library
desugaring 让 `java.time` 能在 7.x 上跑，`aapt dump badging` 也一直是 `sdkVersion:'24'`。
但 1.2.3 之后又陆续引入了三处会真实拦住 7.0 设备的东西，本版逐一修掉：

### 1. 主题里的 API 27 属性（真正的低版本隐患）

`res/values/themes.xml` 里写了

```xml
<item name="android:windowLayoutInDisplayCutoutMode">shortEdges</item>
```

该属性是 **API 27（Android 8.1）** 才有的，却放在基础 `values/`，Android 7.0/7.1
解析主题时会遇到未定义的 android 属性；部分厂商定制系统因属性 id 冲突会直接报错。
lint 的 `NewApi` 检查明确报出：

```
themes.xml:7: Error: android:windowLayoutInDisplayCutoutMode requires API level 27 (current min is 24)
```

**修复**：拆成两层主题，基础主题不含任何 API 26+ 属性：

- `res/values/themes.xml`：`Theme.NasPhotoTV.Base`（windowBackground / 透明状态栏与导航栏 /
  windowNoTitle / windowActionBar）+ `Theme.NasPhotoTV` 继承它；
- `res/values-v27/themes.xml`：同名 `Theme.NasPhotoTV` 继承 Base，只加
  `windowLayoutInDisplayCutoutMode`。

API 24/25/26 只会加载 `values/` 下的基础主题，不会再解析刘海屏属性；API 27+ 行为不变。

### 2. leanback 特性被声明为「必需」

`AndroidManifest.xml` 里 `android.software.leanback` 是 `required="true"`。
不少国产 Android 7.x 电视盒子 / 老平板并不实现 leanback 特性，应用市场和部分安装器
会据此直接过滤掉安装包 —— 这是「7.0 装不上」最常见的拦路点。

**修复**：改为 `required="false"`。Android TV / Google TV 仍通过 `LEANBACK_LAUNCHER`
正常进入，横屏 D-Pad 交互完全不变。另外 `screenOrientation="landscape"` 会让 aapt
隐含推导出一个 required 的 `android.hardware.screen.landscape`，也显式声明为
`required="false"`，让竖屏设备同样能装（运行时仍强制横屏）。

`aapt dump badging` 现在三项全是 `uses-feature-not-required`：

```
uses-feature-not-required: name='android.hardware.screen.landscape'
uses-feature-not-required: name='android.hardware.touchscreen'
uses-feature-not-required: name='android.software.leanback'
```

### 3. 只有 v2 签名

AGP 8 在 `minSdk >= 24` 时默认只签 APK Signature Scheme v2。Android 7.0 是首个支持
v2 的版本，理论上没问题，但部分国产 7.x 定制系统的 v2 校验实现不完整。
**修复**：`signingConfigs` 里显式 `enableV1Signing = true` + `enableV2Signing = true`
（debug / release 都加）。产物里同时有 `META-INF/CERT.SF` / `CERT.RSA` / `MANIFEST.MF`，
`apksigner verify --min-sdk-version 23 --max-sdk-version 23` 退出码 0，
即 v1(JAR) 与 v2 双签都有效；新系统不受影响。

### 4. 把 lint 变成可用的守门员

之前 `lintDebug` 会因项目没有 androidTest 源码、离线缺 `androidx.collection:collection-jvm:1.4.0`
而失败，也一直没跑过 `NewApi`。本版：

- `lint { checkTestSources = false }`，联网补依赖后 `lintDebug` 能跑通；
- 禁用项目既有的三类基线误报（`UnsafeOptInUsageError`(media3 `@UnstableApi`)、
  `RestrictedApi`、`UnusedContentLambdaTargetStateParameter`），它们与低版本兼容无关；
- **保留 `NewApi` / `InlinedApi` 等检查继续生效**。修完主题后 lint 报告 **0 errors / 35 warnings**。

### 5. 文档纠偏

README 里还留着「minSdk 26」「Android 8.0（API 26）及以上」「leanback required」等
1.2.3 之前的旧描述，容易造成「不支持 7.0」的误解。现已统一为
**minSdk 24 / Android 7.0 及以上 / leanback 可选**（CONTRACT.md 同步）。

## 兼容性盘点

| 项 | 状态 |
|---|---|
| `minSdk` / `targetSdk` / `compileSdk` | 24 / 34 / 35 |
| `java.time` 等 API 26 类 | `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4")` 脱糖 |
| 代码里的高版本 API | `AppUpdate`(≥28 签名读取)、`MediaImage`(≥28 ImageDecoder)、`VideoCapabilityProbe`(≥29 AV1) 均有 `SDK_INT` 保护 |
| 依赖最低要求 | 合并后的 manifest 未把 `minSdk` 抬高到 24 以上（Compose 1.7.6 / media3 1.5.1 / Coil 2.7 / okhttp 4.12 均 ≤21） |
| 主题资源 | 基础 `values/` 无 API 26+ 属性 |
| 设备特性 | leanback / touchscreen / screen.landscape 全部非必需 |
| 签名 | v1(JAR) + v2 双签 |
