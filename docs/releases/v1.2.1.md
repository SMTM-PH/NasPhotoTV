## 修复：开启两步验证的账号连不上 NAS

### 用户反馈

> 测试失败：登录成功但 NAS 没有返回 AccessToken

`1.2.0` 及更早版本在账号开启**两步验证**时必定失败，且报错文案没有任何指导意义。

### 根因

飞牛在「密码正确、但当前设备未被信任」时会返回：

```json
{ "errno": 0, "result": "succ", "isBindTwofaSecret": true, "accessToken": "临时凭证" }
```

注意 `errno` 是 0、`result` 是 `succ`，但**没有 `token`** —— 正确的后续动作是拿 `accessToken`
在同一连接上提交 `user.2fa.loginVerify` + 6 位动态码，服务端才下发真正的 `token`。

旧代码只判断 `token` 是否为空，于是把「还需要一步验证」当成「登录成功但没给 token」，
既没有提示用户，也没有去提交动态码。用户的账号明明开了两步验证，App 却永远连不上。

### 修复内容

1. **识别两步验证挑战**：登录响应分类为「成功 / 需要动态码 / 需要先绑定验证器 / 真的缺 token」，
   不再用一句含糊的报错兜底。判定同时兼容 `true` / `"true"` / `1` 三种布尔写法
   （不同 fnOS 版本不一致，`optBoolean` 读数字会得到 false）。
2. **真正完成两步验证**：新增 `verifyTwoFactor(code)`，用与登录相同的 RSA + AES-CBC 加密信封，
   在**登录用的同一条 WebSocket** 上提交 `user.2fa.loginVerify`
   （字段 `accessToken` / `code` / `stay=2` / `isTrustedDevice=true` / `did` / `deviceType` / `deviceName`），
   成功后接上 `token` / `secret` 并恢复心跳。
3. **固定设备标识 `did`**：原来每次登录都随机生成，等于每次都是新设备，
   即使勾了「信任此设备」下次冷启动照样要验证码。现在首次生成后写入
   `SharedPreferences`（`fnos_device/install_id`），信任状态才能跨重启生效。
4. **电视端动态码输入**：复用设置页的电视键盘并新增纯数字模式（0-9 / 删除 / 完成），
   遥控器方向键选数字、确认键输入、BACK 取消。
5. **两处入口都接上**：
   - 设置页「测试连接」：密码通过后弹动态码键盘，验证成功才显示「测试通过」；
   - 首屏加载：捕获挑战后弹键盘，验证通过自动重新拉取媒体库。
6. **准确的错误提示**：
   - 验证码错误 / 过期（`errno 135168`）→「动态验证码错误或已过期，请重新输入」，保留会话可直接重输；
   - 连续输错密码导致 IP 被封（`errno 131089`）→「登录失败次数过多，NAS 已临时封禁本机 IP」；
   - 管理员强制两步验证但账号只绑了邮箱 → 明确告知「电视端收不到邮件，请改用验证器」；
   - 真正缺 `token` 时，把 NAS 实际返回的字段名一并列出，便于下次排查。

### 顺带修复：访问码网关的 cookie 会被覆盖

排查这次问题时在真机（本机 fnOS 已开启访问码）上确认了网关行为：

- `GET /access_code_verify` 带 `x-access-code: base64(访问码)` 校验，成功返回 **204** 并下发
  `os-access-code`（HttpOnly、网关级凭证）；失败返回 **401**。
- 该 cookie 是后续所有请求的前提：**不带它连 WebSocket 都握不上手**（直接 401）。

`InMemoryCookieJar` 原来按 host **整桶替换** cookie 列表。访问码 cookie 只在下发它的那一次响应里出现，
之后任何一次响应只要带了别的 `Set-Cookie`，它就会被静默覆盖 —— 表现为媒体库突然全部 401、重启才好。
现在改为按 cookie 名合并、同名才更新，并顺手清理已过期的条目。

另外补了两处容错：

- 网关返回 HTTP 401（访问码 cookie 过期）时，原来直接抛「NAS 返回 HTTP 401」，
  而按业务 `code` 判定的重登分支根本看不到它。现在会重新校验访问码后重试一次。
- 访问码填错时的提示从「访问码校验失败（HTTP 401）」改为「访问码不正确，请在设置里重新填写」。

### 顺带修复

- **输入浮层抢焦点**：电视键盘原来与页面同层，底层页面（设置列表、媒体库导航）
  会把自己的焦点抢回去，遥控器按键跑到遮罩底下。改用 `Dialog` 独立窗口承载，
  底层从此收不到按键事件 —— 这个问题在 1.2.0 的所有输入框上都会偶发。
- **会话不泄漏**：离开设置页或取消验证时会关闭半登录的 WebSocket，
  不会在 NAS 上留一条长期挂着的连接。

## 验证

- 单元测试新增 `FnOsLoginReplyTest`（8 个用例）：成功 / 挑战 / 需先绑定 / 邮箱验证 / 缺 token 字段 /
  `"true"` 与 `1` 形式的布尔；`InMemoryCookieJarTest`（4 个用例）：访问码 cookie 不被无关
  `Set-Cookie` 覆盖、同名更新、过期不发送、按 host 隔离。合计 31 个用例全绿。
- 模拟器实测（Android TV 1080p）：动态码键盘渲染、遥控器输入、BACK 取消、取消后回到可重试的错误页均正常。
- 真机链路：本机 fnOS（1.2.1000）走加密信封提交 `user.2fa.loginVerify`，
  服务端按预期返回业务错误 `135168`（假 accessToken），证明请求结构与加密方式被接受。
- 访问码链路（测试机上开启访问码后实测）：正确访问码可正常加载媒体库；
  故意填错则显示「访问码校验失败（HTTP 401）」，与预期一致。

> 说明：本机没有可用的两步验证账号，因此「输入正确动态码 → 拿到 token」这一步未在真机跑通；
> 该路径的请求字段与飞牛 Web 端 `useTfaLogin` 的实现逐字段核对一致。
