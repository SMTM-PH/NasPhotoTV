# NAS Photo TV 1.2.4 发布说明

- 发布日期：2026-11-14
- 版本：`1.2.4`（versionCode 10）
- 安装包：`NasPhotoTV-1.2.4-release.apk`（**正式签名**，推荐）/ `NasPhotoTV-1.2.4-debug.apk`（debug 签名）
- release 包 SHA-256：`见 Release 页附件`

## 反馈问题

> 苹果的实况（Live）照片点开就会自动播放，而且反复不停，不符合使用逻辑。
> 希望点进照片是静态的，按某个键才播放，播放完一次回到静态，再按再播。

## 修复：实况照片按需播放

旧行为：点开实况照片，动态片段静音**无限循环**自动播放。

新行为（完全按反馈的预期）：

1. **点开默认静态**：进入看图只显示静止照片，不创建播放器、不消耗解码资源；
2. **确认键播放一次**：焦点在照片上按 **确认 / ENTER**，动态片段从头播放一遍；
3. **播完自动回静态**：片段播到末尾停住（画面停在最后一帧），不再循环；
4. **再按再播**：再次按确认键重新从头播放；
5. 播放期间右上角提示「实况播放中 · 播完自动回到静态」；
6. 2× 放大时仍然只显示静图（与旧行为一致）。

普通照片的确认键仍是「弹出/收起工具条」；视频、全景照片的按键逻辑不受影响。

## 附：正式签名 release 包（针对 TCL/国产 ROM 的 INSTALL_FAILED_VERIFICATION_FAILURE）

反馈：TCL 55T5M（Android 11，armeabi-v7a）安装 1.2.4-debug 报 `INSTALL_FAILED_VERIFICATION_FAILURE`；
包完好、架构/版本/leanback 满足，关闭校验、`adb install -t` 均无效。debug 包是自签且仅 v2 scheme，
疑似被国产 ROM 的风险检测拦截（「Android Debug」证书 + 无 v1 是常见触发点）。

处置：
1. 生成专用 release keystore（RSA 4096，有效期 30 年，`CN=NasPhoto TV`），**不进 git**（`.gitignore` 已排除 `keystore/`）；
2. `app/build.gradle.kts` 增加 `signingConfigs.release`：有 keystore 时 release 自动用正式签名，没有则退回 debug 签名（CI 可构建）；
3. release 包用 **v2 + v3** 双 scheme 签名并 zipalign（`apksigner verify` 通过；targetSdk 34 下 v1(JAR) 被系统策略排除，Android 7+ 全部接受 v2/v3，不影响安装）；
4. 证书指纹：SHA-256 `e63c6b9dfb8870d29b3afc3b6e9657cef6799cdfe3688410b9de4d70e89a525a`，SHA-1 `92254be0b9861f74bdd86eb0619eb0279bca3623`；
5. 模拟器实测：release 包安装成功、启动正常、无崩溃。

注意：**debug 包与 release 包签名不同，不能互相覆盖安装**；从 debug 升级到 release 需先卸载（会清掉本应用的设置与缓存）。今后 Release 页同时提供 debug / release 两个附件。

## 实现说明

- `LivePhotoVideo`：`REPEAT_MODE_ONE`（无限循环）改为 `REPEAT_MODE_OFF`（播一遍停）；
  `playWhenReady` 不再跟随「进入看图」置 true，只有显式的播放请求才 `play()`；
  每次请求 `seekTo(0)` 从头播。
- `PhotoViewerState`：新增 `livePlaybackRequest`（递增信号）与 `livePlaying`（回写当前状态）。
- `StageContent` 按键分发：实况照片的确认键从 `toggleChrome` 改为 `playLiveOnce()`。

## 验证

- 单元测试 36 个全绿（无回归）。
- 模拟器（Android TV 1080p）：
  - 看图内连续滑动切换 32 张照片，logcat **0 次** ExoPlayer 初始化 —— 证明「点开/切换」不再创建播放器（旧版打开实况图会立刻创建并循环播放）；
  - 普通照片确认键仍正常弹出工具条（截图前后对比确认）。
- 局限：本机 NAS 库中没有实况图样本（全库 `isLive=1` 为 0，无法在模拟器端到端验证「确认键播放一次」的完整链路）；该路径的验证依据是代码级检查（无残留的自动播放分支）+ 静态编译通过。请在有实况图的设备上实际确认，如行为不符请反馈具体现象。
