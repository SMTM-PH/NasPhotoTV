# NAS Photo TV 1.2.6 发布说明

- 发布日期：2026-11-17
- 版本：`1.2.6`（versionCode 12）
- 基于：1.2.5（竖屏视频 / 4K 缓冲 / 反向代理地址）

## 反馈问题

> 1.2.4 已试用：人物点进去能显示全部照片了；相册点文件夹只显示主文件夹，子文件夹没显示；
>    点图库进去只显示最近 9 年，2000–2017 都没显示，这点还没修复。
> 2. 选择相册时应该自动切换全屏，呈现美感和大屏优势，现在界面太小。
> 3. 相册缩略图太粗糙，应该小一些，显得 DPI 大一些、更精致。

## 一、图库只显示最近 9 年（再次修复）

v1.2.3 已经把 `gallery/getList` 改成按 offset 逐页拉取，但翻页终止条件写成了：

```kotlin
val hasNext = data.optBoolean("hasNext", page.size >= 500)
if (!hasNext || page.size < 500) break
```

即必须 **hasNext 与「本页满 500」同时成立**才继续。用户 NAS 上每页实际返回不足 500 条
（或 `hasNext` 回的是 `"1"` / `1` 而不是 JSON `true`），于是第一页后就停止，
仍然只有最近约 9 年。

修复（`data/Paging.kt` + `FnOsMediaRepository.getRecent()`）：

- 改为 **OR 语义**：`hasNext` / 满页 / `total` 未取满，任意一个信号说「还有」就继续翻页；
- `hasNext` 兼容 `true` / `"true"` / `1` / `"1"`；
- 按媒体 id 去重，服务端忽略 offset 重复回传同一页时立即终止，不会死循环；
- `offset` 按服务端原始条数推进，解析失败的条目不会让后续页错位；
- 同一套判定也用于文件夹文件列表（`getFolderMedia`），避免大文件夹只显示前 200 项。

新增 `PagingTest`（8 个用例）覆盖短页 + hasNext、`hasNext` 各种类型、
full page 无 hasNext、total 未取满、重复页、硬上限等分支。

## 二、文件夹只显示主目录（已修复）

根因：`photo/folder/list` 返回的是**已加入扫描的根目录**（如 Photos / Video），
本身没有子目录；旧代码只映射这一层，`folder_view/getFileList` 里的目录项又被
媒体解析（要求 `id > 0`）直接丢弃，所以既看不到子文件夹也无法下钻。

修复（`FnOsMediaRepository.getFolders()`）：

- 保留 `photo/folder/list` 根目录的真实照片/视频计数；
- 从 `photo/folder/view` 的目录树递归展开所有子文件夹
  （兼容 `children` / `subfolders` / `childList` / `fileList` 等字段名，防环 + 深度/数量上限）；
- 若该接口只给根目录，则对每个根目录读一次 `folder_view/getFileList`，
  从文件列表里识别目录项作为兜底；目录项若只有名字/isDir 没有完整路径，
  用父目录路径 + 名字拼出来（实测 NAS 上真实子目录为
  `/vol1/1000/Photos/{MobileBackup,PhotoLibrary,DJI_001}`）；
- 合并去重后全部写入 `folderCache`，`NasFolder` 新增 `parentId` / `depth`；
- 文件夹 Tab 现在直接显示所有扫描根目录与子目录，子目录带「子文件夹 · 路径」说明，
  点进去用同一套 `folderId` + `folderPath` 拉取媒体，按年份分组不变。

新增 `FolderTreeTest`（5 个用例）覆盖真实计数、多层嵌套、媒体项过滤、去重与字段兼容。

> 实测补充（2026-11-18，fnOS CLI 原始请求）：
> - `GET /p/api/v1/photo/folder/list` → 200，只有 `folderId=1 /Photos`（4408 图 + 431 视频）
>   和 `folderId=2 /Video`（142 图 + 313 视频）两个根目录，无子目录字段，确认根因；
> - `file ls-dir /vol1/1000/Photos` → 磁盘上确有 `MobileBackup/`、`PhotoLibrary/`、`DJI_001/`
>   三个子目录，与用户反馈一致；
> - `GET /p/api/v1/photo/folder/view` 与 `folder_view/getFileList` 经 CLI 代理返回 **403 Forbidden**
>   （该 CLI 只放行 folder/list、gallery/getOne 等白名单路径），因此无法抓到子目录接口的
>   原始 JSON。实现继续保留多字段名兼容；若真机仍只显示根目录，需要 App 侧抓包或贴出
>   该接口响应后再补一条精确解析分支。

## 三、选择相册自动全屏（已实现）

窗口层面本来就是全屏（`MainActivity` 已隐藏系统栏、edge-to-edge）；
问题在于进入相册详情后，首页的**满屏照片背景消失**，顶栏和底部提示还在，
看起来就是「一张小网格贴在纯黑底上」。

修复（`LibraryScreen`）：

- 进入相册 / 人物 / 智能分类详情时判定为 `detailOpen`；
- 用该相册（或人物、分类）的封面渲染**满屏背景 + 上下渐变压暗**，
  保留大屏沉浸感并保证标题可读；
- 详情态隐藏顶栏与底部导航提示，让网格铺满整屏；返回后原样恢复；
- 遥控器 BACK / 返回按钮的既有行为不变。

## 四、缩略图更小更清晰（已实现）

此前卡片尺寸常量是按 1920×1080dp 画布写的，而 1.2.2 起全局强制 960×540dp 设计画布：
相册卡 408dp 在 1080p 上要画 816 物理像素，却只请求 640px 缩略图，
**源像素比显示像素还少**，所以显得粗糙。同时一行 3–4 张大卡远超画布宽度。

修复：

| 项 | 旧值 | 新值 |
|---|---|---|
| 相册网格列数 / 卡片 | 4 列 / 408×200dp | **3 列 / 256×152dp** |
| 照片网格列数 / 卡片 | 6 列 / 244×158dp | **4 列 / 192×124dp** |
| 时间线分桶卡片 | 5 列 / 340×200dp | **3 列 / 256×152dp** |
| 相册封面请求像素 | 640 | **960**（`TvImage.AlbumCoverPx`） |
| 照片/年份缩略图请求像素 | 480 | **640**（`TvImage.MediaThumbPx`） |

- 列数不再根据系统 `screenWidthDp` 分支（设计画布已被归一化，分支只会导致 4K 溢出），
  统一使用固定常量；
- 首页「客厅相册」胶片条本来就是oversample（约 2.1×），保持不变；
- 新增 `TvImage` token，请求像素集中管理；`MediaImage` 仍按实际密度放大并封顶 1920，
  4K 上不会发虚也不会因位图过大拖垮低内存电视。

效果：卡片面积约减半，同屏可见内容更多；1080p 上相册封面约 1.9× 过采样，
缩略图从「糊」变「锐」，更精致。
